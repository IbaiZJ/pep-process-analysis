# pep-process-analysis

Who decides what goes into Python? This project studies the **Python Enhancement
Proposal (PEP)** process: who proposes changes, who decides, and how that changed when
Python's creator stepped down in 2018. It compares what the official documents say
with what the Git history of [python/peps](https://github.com/python/peps) shows.

Applied DevOps, Homework 1 (2026/27). Full analysis: **[docs/report.md](docs/report.md)**.

## Main findings

- **About a third of language proposals end in a no.** Of 489 closed Standards Track
  PEPs, 23.7 % were rejected and 11.0 % withdrawn by their own authors.
- **Saying no is slow.** Median time to acceptance is 148 days, to rejection 275.5 and to
  withdrawal 735.5.
- **When the BDFL stepped down, decisions stopped.** Between July 2018 and February 2019
  no Standards Track PEP was decided; the only 8 decisions were about governance.
- **The Steering Council shares the work out.** Decisions by a named delegate rose from
  12.5 % to 31.2 %, and decisions with a recorded `Resolution` link from 28.0 % to 78.3 %.
- **Open, but concentrated.** 370 people have written PEPs and over half wrote just one,
  yet 21 frequent authors appear on 49.5 % of all PEPs.

Numbers come from `results/summary.md`, generated by the code below.

## Toolchain

Tested on Linux with exactly these tools:

| Tool | Version | Notes |
| --- | --- | --- |
| Ubuntu | 24.04.5 LTS | WSL 2 on Windows during development |
| git | 2.43.0 | Ubuntu 24.04 package |
| uv | 0.13.9 | Installs Python and all dependencies |
| Python | 3.13.18 | Downloaded and managed by uv (pinned in `.python-version`) |

Python libraries are pinned in `uv.lock`: matplotlib 3.11.2 (charts) and, for
development, Ruff 0.17.6. No other programs are called. An internet connection is needed
the first time, to clone python/peps and download Python and the libraries.

## How to run

From a fresh clone, in the repository root:

```bash
# 1. Get the code
git clone https://github.com/IbaiZJ/pep-process-analysis.git
cd pep-process-analysis

# 2. Run the whole analysis
uv run --locked pep-analysis
```

Step 2 does everything:

1. clones python/peps into `data/peps/` if it is not there yet, and checks that the
   pinned commit exists;
2. reads the PEP files and the Git history at the pinned commit;
3. writes every table, chart and `results/summary.md` to `results/`.

It takes under a minute (most of it is the clone). Running it again gives identical
results.

The project needs no root access and writes nothing outside this directory: the clone,
the virtual environment (`.venv/`) and all results stay here and are ignored by git.
Deleting the directory removes everything except uv's normal download cache.

## Code quality checks

```bash
uv run --locked ruff format --check .

```

Both must pass with no errors or warnings. Ruff is configured in `pyproject.toml`.

## What is where

| Path | Contents |
| --- | --- |
| `docs/report.md` | The analysis: stakeholders, data, one traced PEP, interpretation |
| `docs/worklog.md` | Step-by-step log of the work, with commands and decisions |
| `docs/links.md` | Every external source, with access date |
| `src/pep_analysis/config.py` | Pinned commit, paths, governance periods |
| `src/pep_analysis/fetch.py` | Clones python/peps and checks the pinned commit |
| `src/pep_analysis/headers.py` | Reads PEP headers at the pinned commit |
| `src/pep_analysis/clean.py` | Cleans the headers and logs every rule |
| `src/pep_analysis/history.py` | Rebuilds status history and decision dates from Git |
| `src/pep_analysis/analysis.py` | Outcome and timing tables, `summary.md` |
| `src/pep_analysis/participation.py` | Authors, delegation, sponsors, discussion venues |
| `src/pep_analysis/charts.py` | Charts |
| `pyproject.toml`, `uv.lock`, `.python-version` | Project, pinned dependencies, Python version |
| `data/` | Clone of python/peps (generated, not committed) |
| `results/` | Tables, charts and `summary.md` (generated, not committed) |

Results contain only counts and shares, never personal data such as e-mail addresses.
